# 设备管理

## 设备管理概述

### I/O 设备的特点

I/O 设备种类多、差异大。

按传输速度：
- 低速设备；
- 中速设备；
- 高速设备。

按信息交换单位：
- 块设备：以块为传输单位，每个块可独立读写，如硬盘、CD-ROM、U 盘。
- 字符设备：以字符为单位发送或者接收字符流的设备，不可寻址，如打印机、鼠标、键盘、网卡。

按共享属性：
- 独占设备；
- 共享设备。

> 设备管理的一个核心难点：外设速度差异巨大，但系统仍要提供统一、稳定且高效的访问方式。

### 设备管理目标

方便使用：
- 屏蔽不同外设差异；
- 对不同设备提供统一使用方式；
- 协调设备的并发使用。

提高效率：
- 提高 I/O 访问效率；
- 匹配 CPU 与不同速度外设之间的处理节奏。

方便控制：
- 支持设备增加、删除；
- 支持新设备类型；
- 方便 OS 对设备统一管理。

### 设备管理功能

设备管理主要功能：
- 提供设备使用接口：命令行接口和编程接口；
- 分配与释放设备、控制器、通道等资源；
- 管理设备访问与控制，包括并发访问和差错处理；
- 实现 I/O 缓冲和调度，提高访问效率。

### 统一 I/O 接口

#### 设备即文件

UNIX 将设备抽象为特殊文件，从而让用户通过统一的文件接口访问多种设备。

例如：

```c
FILE *fd = fopen("/dev/something", "rw");
fprintf(fd, "Count %d\n", i);
fclose(fd);
```

常见接口：
- 块设备：`read()`、`write()`、`seek()`，支持随机读写；
- 字符设备：`get()`、`put()`，通常是顺序读写；
- 网络设备：通过 socket 接口访问。

#### 驱动程序与 VFS

设备驱动程序实现标准接口。

以 Linux 字符设备为例：
- 应用程序调用 `open`、`read`、`write`、`ioctl` 等库函数；
- 进入系统调用接口，如 `sys_open`、`sys_read`；
- VFS 根据文件描述符和 inode 判断设备类型；
- 内核根据主设备号、次设备号找到对应驱动；
- 通过 `file_operations` 中的函数指针调用驱动的 `open`、`read`、`write` 等函数。

核心思想：
- 应用看到的是统一文件接口；
- OS 内部通过驱动程序完成设备相关细节。

## I/O 硬件基础

### 总线

总线（Bus）是 CPU、内存和 I/O 设备之间通信的主要通路。

CPU 读取一个字的大致过程：
- 将地址放到地址总线；
- 在控制线上发出读信号；
- 数据总线返回数据。

典型 PC 结构中，I/O 常由南桥或类似芯片组负责：
- PCI/PCIe；
- 磁盘控制器；
- USB 控制器；
- 音频；
- 串行 I/O；
- 中断控制器；
- 定时器。

### 设备控制器

设备控制器是 I/O 设备的电子组件，通常以板卡或芯片形式存在。

作用：
- 向下与具体硬件设备通信；
- 向上为 CPU 提供较高层接口；
- 屏蔽底层硬件接口复杂性。

控制器通常包含：
- 数据寄存器；
- 控制寄存器；
- 状态寄存器；
- 设备侧的数据信号、控制信号、状态信号接口。

### CPU 访问控制器的方式

I/O 指令方式：
- I/O 端口有**独立**地址空间；
- CPU 使用专门指令访问，如 x86 的 `in/out`；
- 例如 `out 0x21, AL`。

内存映射 I/O：
- 控制器的内存/寄存器映射为物理内存空间的一部分；
- 对I/O的操作通过 `load` 和 `store` 指令来实现；
- 常见于 MIPS 等体系结构，也广泛用于现代系统。

## I/O 软件原理

### I/O 软件目标

#### 设备无关性

应用程序访问输入输出时，应尽量不依赖具体设备类型。

例如：
- 从硬盘读文件；
- 从 DVD 读文件；
- 从 U 盘读文件。

用户使用方式可以相同，底层差异由 OS 和驱动处理。

#### 统一命名

设备需要统一命名方式：
- 使用字符串；
- 使用整数编号；
- UNIX 中把设备纳入文件系统路径层次。

#### 错误处理

错误应尽可能在靠近硬件的层次处理：
- 控制器处理底层硬件错误；
- 驱动处理设备相关错误；
- 设备无关软件向上报告通用错误。

目标是缩小错误影响范围。

#### 同步、异步与缓冲

大多数物理 I/O 操作**本质上是异步**的，但 OS 往往为用户**封装成同步**接口。

> 同步：用户发出请求后等待结果。
> 异步：用户发出请求后立即返回，I/O 完成后再通过通知、回调或事件机制告知用户。

缓冲：
- 缓冲设备数据用以进行检查
- 协调数据的生产和消费
- 性能优化

### 用户访问 I/O 的方式

#### 阻塞与非阻塞

I/O 功能实现角度

阻塞 I/O：
- 进程发出读写请求后，如果数据或设备未准备好，则进入睡眠；
- 例如 `read()` 等待数据准备完成。

非阻塞 I/O：
- 请求发出后立即返回；
- 数据或设备准备好后，需要通过 `select()`、事件通知等机制处理。

![alt text](image-1.png)

#### 同步与异步

同步/异步是从用户进程是否等待结果的角度区分。

同步：
- 发出请求后等待结果返回；
- 常见于快速控制命令。

异步：
- 发出请求后立即返回；
- 内核完成数据搬运后再通知进程；
- 常用于窗口事件、网络数据发送等。

> 阻塞/非阻塞关注“调用是否立刻返回”，同步/异步关注“结果由谁在什么时候完成并通知”。

### I/O 控制技术

#### 程序控制 I/O

程序控制 I/O（PIO, Programmed I/O）由程序发起并等待操作完成，数据每次读写都经过 CPU。

典型方式是**轮询或忙等**：
- CPU 不断查询设备状态；
- 设备准备好后传输数据。

优点：
- 实现简单。

缺点：
- CPU 利用率低；
- 外设处理数据时 CPU 只能等待。

#### 中断驱动 I/O

中断驱动方式中，CPU 发起 I/O 后可以继续执行其他工作；当外设完成操作后，通过**中断**通知 CPU。

优点：
- CPU 不必忙等，提高 CPU 利用率；
- 可处理不确定事件。

缺点：
- 每次输入/输出完成都可能中断 CPU；
- 中断处理有上下文保存和恢复开销，浪费 CPU 时间；
- 更适合低速或中速设备。

![alt text](image-2.png)

中断处理一般包括：
- 关中断（CPU屏蔽其他新的中断请求）；
- 保存现场；
- 设置中断处理堆栈；
- 执行中断服务程序；
- 恢复现场；
- 开中断；
- 返回或调度下一个进程。

常见术语：
- ISR：中断服务程序，是发生中断时所应执行的处理代码；
- Interrupt Vector：中断向量，即中断服务程序入口地址；
- IVT/IDT：中断向量表或中断描述符表（x86版中断向量表），为关联中断请求（索引）和中断服务程序的数据结构。

#### DMA

DMA（Direct Memory Access，直接存储访问）让 DMA 控制器直接在内存和外设之间成批传输数据。

过程：
1. CPU 设置 DMA 控制器寄存器，如内存起始地址、传输字节数、方向；
2. DMA 控制器完成内存与外设之间的数据交换；
3. 传输完成后，DMA 控制器向 CPU 发出中断。

优点：
- CPU 只需干预开始和结束；
- 成批数据传输不需要 CPU 参与；
- 适合高速设备。

缺点：
- CPU 仍要设置传输参数；
- ~~DMA 控制器占用总线；~~
- 设备增加可能需要更多控制器~~或通道资源~~。

DMA 与中断方式的区别：
- 中断方式常在每个数据单位完成后中断 CPU；
- DMA 在一批数据完成后才中断 CPU；
- 中断方式的数据传送由 CPU 在中断处理中完成；
- DMA 由控制器直接完成内存与设备之间的数据传送。

#### 通道技术

I/O 通道是**专门负责输入输出的处理器**，独立于 CPU，有自己的指令体系。

基本思想：
- OS 构造通道程序并放入内存；
- 通道执行通道程序；
- 一次通道程序可完成多组 I/O 操作。

优点：
- 比 DMA 进一步减少 CPU 干预；
- 可进行较复杂的 I/O 控制。

缺点：
- 成本较高。

通道类型：
- 字节多路通道：按字节分时交叉工作，适合低速/中速设备；
- 数组选择通道：一次为一台高速设备传送一批数据；
- 数组多路通道：结合分时服务与高速成批传输，支持多设备并行。

通道与 DMA 的区别：
- DMA 主要由 CPU 设置传输方向、地址和长度；
- 通道有自己的指令和程序，独立处理能力更强；
- DMA 通常服务一台或少数同类设备；
- 通道可同时管理多种设备。

## I/O 软件概述

### 总体层次

I/O 软件通常分为：
- 中断处理程序；
- 设备驱动程序；
- 与设备无关的软件；
- 用户空间 I/O 软件。

目标：
- 把硬件复杂性隐藏在底层；
- 对上层提供统一接口；
- 尽量让设备相关代码局限在驱动中。

### 中断处理程序

中断处理程序处于系统底层，用于屏蔽中断处理的复杂性。

设备驱动程序启动 I/O 后，通常阻塞自己或等待事件，直到中断处理程序在 I/O 完成时唤醒相关等待者。

### 设备驱动程序

设备驱动程序是针对**特定设备控制**的代码。

特点：
- 不同控制器差异大；
- 一个驱动通常针对一类相似设备；
- OS 定义驱动接口规范；
- 驱动常由设备生产商开发；
- 通常位于 OS 底层。

#### 驱动程序功能

- 初始化设备；
- 启动设备并发出 I/O 命令；
- 检查 I/O 请求合法性；
- 将抽象 I/O 请求转换为物理设备请求；
- 查询设备状态，对请求排队；
- 处理同步/异步操作；
- 向上层报告数据或错误。

#### 驱动程序特点

- I/O进程与设备控制器之间的通信程序；
- 驱动程序与设备特性紧密相关；
- 可重入设计；
- 支持设备增加、删除；
- 处理异常和错误；

设备驱动具有的共性

- 核心代码：设备驱动是内核的一部分，出错将导致系统的严重错误。
- 与内核接口：设备驱动必须为内核提供一个标准接口。例如终端驱动为内核提供一个文件I/O接口
- 可使用内核的服务：可以使用标准的内核服务如内存分配、中断发送和等待队列等
- 动态可加载：在内核模块发出加载请求时加载；在不再使用时卸载，内核能有效地利用系统资源

#### 设备驱动程序的组成

**自动配置和初始化**子程序：检测所要驱动的硬件设备是否存在、是否正常。如果该设备正常，则对该设备及其设备驱动程序需要的软件状态进行初始化。在初始化的时候被调用一次。

**服务于I/O请求**的子程序：调用该子程序是系统调用的结果。执行该部分程序时，系统仍认为是和调用进程属同一个进程，只是由用户态变成核心态，具有进行此系统调用的用户程序的运行环境，

#### 驱动程序接口

OS 通常通过函数指针表调用驱动程序。

这种方式的意义：
- 驱动可动态加载；
- 内核无需为每个驱动重新编译；
- 不同设备可以实现相同接口函数。

Linux 中的 `file_operations` 就是典型例子。

### 与设备无关的软件

#### 作用

与设备无关的软件向用户层提供通用 I/O 功能，把具体设备差异留给驱动程序封装。

主要功能：
- 提供和驱动程序的统一接口；
- 缓冲；
- 错误报告；
- 分配与释放专用设备；
- 提供与设备无关的块大小。

#### 统一驱动接口

如果每个驱动接口都不同，OS 调用会非常复杂。

标准化接口后：
- OS 通过统一函数表间接调用驱动；
- 驱动实现规定的入口函数；
- 上层软件不需要知道硬件细节。

#### 缓冲技术

缓冲技术的作用：
- 匹配 CPU 与外设速度；
- 减少中断次数；
- 提高 CPU 与 I/O 设备之间的并行性；
- ~~方便数据检查和格式转换~~。

常见形式：
- 无缓冲；
- 用户空间缓冲；
- 内核空间缓冲；
- 用户空间 + 内核空间缓冲；
- 双缓冲。

##### 单缓冲
- 一个缓冲区；
- CPU 和外设**轮流**使用（设备往缓冲区写、用户进程从缓冲区读，这两件事不能同时进行。）。

##### 双缓冲

工作原理：设备先把数据充满 A 缓冲；当用户进程从 A 缓冲读取数据时，设备可以不停下，直接去充满 B 缓冲。当 B 充满、A 读空后，两者角色对调（反转）。

优势：实现了输入和传送的**并行**。只要进程处理数据的速度和设备输入的速度差不多，设备和 CPU 就能同时全速运转，几乎没有等待时间。

![alt text](image-3.png)

##### 环形缓冲

- 多个缓冲区组成循环队列；
- 适合 CPU 与外设速度差异较大的场景；
- 本质类似生产者-消费者问题。

##### 缓冲池

缓冲池中包含三种队列：空闲缓冲区队列、输入队列、输出队列。

任何设备或进程需要缓冲时，直接去空闲队列里申请一个，用完后再归还。这种方式实现了内存的高效复用。

- 适合反复使用缓冲区，减少频繁申请释放。

> 缓冲提高了开发便利性和性能，但多层缓冲也可能导致数据多次复制，降低性能。

#### 错误报告

错误可分为：
- 编程错误：参数错误、无效设备等，通常直接返回错误码；
- 实际 I/O 错误：磁盘块损坏、设备故障等，需要从驱动逐层传递。

原则：
- 能在底层处理就在底层处理；
- 不能处理则向上层报告。

#### 设备分配

由于外设资源有限，OS 需要解决设备共享与分配问题。

两类常见方式：
- 在进程间切换使用设备；
- 用虚拟设备隔离独占设备和应用进程。

相关数据结构：
- DCT：设备控制表，每个设备一张，描述设备状态和特性；
- COCT：控制器控制表，每个设备控制器一张；
- CHCT：通道控制表，每个通道一张；
- SDT：系统设备表，全系统一张，记录所有设备状态及 DCT 入口。

设备分配时考虑：
- 设备固有属性：独享、共享、虚拟；
- 分配算法：先来先服务、优先级优先；
- 安全性：是否可能产生死锁；
- 设备独立性：逻辑设备名到物理设备名的映射（实现应用程序与物理设备无关）。

安全分配：
- 进程发出 I/O 请求后阻塞直到完成；
- 可防止死锁，但 CPU 与 I/O 串行，效率低。

不安全分配：
- 进程发出请求后仍可继续运行；
- 效率较高，但需要进行安全性检查。

### 用户空间 I/O 软件

- 库函数
- 假脱机技术
- 数据格式化

#### 库函数

用户空间 I/O 软件通常提供库函数支持系统调用，例如：
- `write`；
- `printf`；
- `scanf`。

库函数与应用程序链接在一起，为用户提供更方便的接口。

#### SPOOLing

SPOOLing（Simultaneous Peripheral Operation On Line）也称假脱机技术或虚拟设备技术。

作用：
- 把独享设备转换成具有**共享**特征的虚拟设备；
- 提高设备利用率；
- ~~缩短应用程序等待实际外设完成的时间~~。

基本思想：
- 系统中有专门的 SPOOLing 程序或守护进程；
- 应用程序只与 SPOOLing 程序交换数据；
- SPOOLing 程序再与真实外设进行实际 I/O。

应用看到的是虚拟 I/O，设备执行的是实际 I/O。

![alt text](image-4.png)

典型例子：
- 打印机管理器；
- 打印作业队列。

特点：
- 应用程序可以很快把输出交给队列；
- 后续由打印管理程序慢慢完成真实打印；
- 独占打印机被虚拟成可共享设备。

## 设备管理实例

### UNIX 设备管理

UNIX 将外设映射为特殊文件，由文件系统按文件方式管理，并向上提供统一接口。

UNIX I/O 可分为：
- 无缓存 I/O：进程 I/O 区域与系统 I/O 模块直接交换数据；
- 有缓存 I/O：经过系统缓冲区管理机构。

有缓存 I/O 包括：
- 系统缓冲区；
- 字符队列。

### 块设备缓冲区管理

块设备缓冲区用于磁盘等外存缓存。

缓存块由两部分组成：
- 缓冲控制块；
- 缓冲数据区。

缓冲控制块常包含：
- 逻辑设备号；
- 物理块号；
- 缓冲区状态，如空闲、延迟写、锁定；
- 指向数据区的指针；
- 哈希队列指针；
- 空闲队列指针。

相关队列：
- 空闲缓冲队列；
- 设备 I/O 请求队列；
- 设备缓冲区队列。

为了快速检索，设备缓冲区队列常按 `(逻辑设备号, 物理块号)` 组织成哈希队列。

常见读写方式：
- 一般读；
- 预先读；
- 一般写；
- 异步写；
- 延迟写。

### 字符设备缓冲区管理

字符设备使用字符队列。

特点：
- 缓冲区中每个字符通常只能读一次；
- 读后被消耗；
- 适合终端、键盘等字符流设备。

字符缓冲区的基本单位可以是 `cblock`，包含：
- 队首/队尾位置；
- 指向下一缓冲区的指针；
- 固定大小的数据区。

### UNIX 设备开关表

UNIX 通过块设备开关表和字符设备开关表描述驱动程序接口。

开关表本质上是一组标准操作入口地址：
- 文件系统通过表项调用对应驱动；
- 驱动向上提供统一接口。

### Streams

Streams 是一种基于消息的模块化驱动程序机制。

目的：
- 降低驱动程序功能重复；
- 通过模块化数据传输通道组织内核和驱动逻辑。

流由读队列和写队列组成，数据可分为：
- 上行流；
- 下行流。

### NT 的 I/O 系统

NT I/O 子系统提供文件化 I/O 函数，支持：
- 打开、关闭、读写；
- 异步 I/O；
- 映射文件 I/O；
- 快速 I/O。

NT 的 I/O 管理器：
- 创建和传递 I/O 请求包 `IRP`；
- 把抽象 I/O 请求传给驱动程序；
- 由核心态驱动转换为硬件设备请求。

NT 采用分层驱动思想：
- 文件系统驱动程序；
- 文件系统过滤器驱动程序；
- 类驱动程序；
- 端口驱动程序；
- 小端口驱动程序；
- 硬件设备驱动程序。

驱动程序常见组成：
- 初始化例程；
- 调度例程集；
- 启动 I/O 例程；
- ISR；
- DPC，用于延迟处理中断后续工作。

## 电源管理

### 基本思想

设备管理不仅关注性能，也关注能耗。

降低能耗的方法：
- 提高硬件能量效率；
- 在设备不用时关闭；
- 应用主动优化能耗。

### 常见设备策略

显示器：
- 用户不需要时关闭；
- 避免应用频繁唤醒；
- 可采用分区显示策略。

硬盘：
- 预测磁盘使用；
- 暂停磁盘工作；
- 增加内存缓存以减少磁盘唤醒。

CPU：
- 休眠；
- 降频；
- 降低电压。

无线通信：
- 空闲时关闭；
- 通过预取和批量传输减少频繁唤醒。

### 移动下载能耗

无线传输是移动设备中最耗电的操作之一。

优化方式：
- 数据预取；
- 绑定传输；
- 减少小数据频繁传输；
- 优先使用高带宽低能耗的连接，如 WiFi。

预取的权衡：
- 预取准确可减少延迟和能耗；
- 预取错误会浪费带宽和电量。

## 小结

本章核心内容：
- 设备管理要屏蔽外设差异，提供统一接口，并提高 I/O 效率；
- I/O 硬件通过总线、控制器、寄存器和端口/内存映射与 CPU 通信；
- I/O 控制方式包括程序控制、中断、DMA 和通道；
- I/O 软件分为中断处理程序、设备驱动、设备无关软件和用户空间软件；
- 缓冲、设备分配和 SPOOLing 是提高效率和共享能力的重要机制；
- UNIX 和 NT 都通过分层接口把设备相关细节封装在驱动体系中。
