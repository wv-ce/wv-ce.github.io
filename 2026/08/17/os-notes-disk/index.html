OS 理论笔记：磁盘管理

磁盘管理

磁盘的工作原理

磁盘的基本结构

磁盘是一种典型的随机存取外存设备，数据记录在旋转盘片表面的磁性介质上，由磁头完成读写。

常见概念：

  • 磁道（track）：盘片表面上的同心圆。
  • 扇区（sector）：磁道被划分出的若干扇形区域，是磁盘读写的基本单位。
  • 柱面（cylinder）：多个盘面上半径相同的磁道组成的集合。
  • 磁头（head）：每个盘面通常对应一个磁头。

传统地址方式是 CHS（柱面 Cylinder、磁头 Head、扇区 Sector），现代系统更多采用 LBA（逻辑块地址）进行统一编号。

温彻斯特磁盘

温彻斯特磁盘的主要特点：

  • 磁头和盘片组件密封；
  • 内部充惰性气体，减小阻力；
  • 磁头更轻更小，可以更靠近盘面；
  • 采用接触起停技术，降低结构复杂度。

这些改进带来了更大的容量、更高的读写速度和更低的成本。

位密度与 ZBR

位密度：沿磁道方向单位长度内可记录的二进制位数，也称线密度。

老式磁盘：

  • 每个磁道的扇区数相同；
  • 外圈磁道更长，因此空间利用率不高。

新式磁盘通常采用 ZBR（Zone Bit Recording，分区记录）：

  • 不同磁道的扇区数不同；
  • 外圈磁道拥有更多扇区；
  • 能提高盘面利用率和总体容量。

从 OS 视角看，磁盘控制器常常会把复杂的物理布局抽象成线性的逻辑块地址。

磁盘缺陷与坏块替换

硬盘实际扇区数比硬盘标签上标定的大，其中一部份用于存储硬盘的固件（硬盘控制器使用）；一部分是用户存储数据的区域，即工作区，也就是硬盘标定容量的扇区；剩下的就是保留区，超过在固件里定义的硬盘容量的那些扇区就称为保留扇区。 实际磁盘不可避免存在缺陷扇区，因此需要缺陷管理机制。

两类缺陷表：

  • P 表（Permanent defect list）：出厂时记录的永久缺陷。
  • G 表（Growth defect list）：使用过程中新增的缺陷。

处理方式：

  • 使用保留扇区替换坏扇区；
  • 对 OS 暴露连续的逻辑块编号。

缺陷加入P表后的扇区结构

缺陷加入G表后的扇区结构

影响：

  • 加入 P 表的坏块通常在低级格式化时就被重映射；
  • 加入 G 表的坏块会导致逻辑连续但物理上不连续，从而拉长寻道距离，降低局部访问性能。

Flash Disk 简述

Flash Disk 是电子式非易失性存储器，相比机械磁盘：

  • 无机械部件，抗震性更好；
  • 访问延迟更小；
  • 功耗更低；
  • 写入通常慢于读取；
  • 容量和价格长期是主要约束。

磁盘的类型

  • 固定头磁盘
    • 每条磁道都有一个磁头
    • 磁头不能移动，速度快，容量小
  • 移动头磁盘
    • 磁头可以活动

磁盘访问时间

访问时间组成

一次磁盘访问时间主要由三部分组成：

  • 寻道时间 Ts：磁头移动到目标磁道所需时间；
  • 旋转延迟时间 Tr：目标扇区转到磁头下方所需时间；
  • 传输时间 Tt：数据真正读出或写入所需时间。

总访问时间：

T=Ts+Tr+TtT = T_s + T_r + T_t T=Ts​+Tr​+Tt​

寻道时间

寻道时间是磁臂从当前位置移动到目标磁道的时间。

常用近似公式：

Ts=m×n+sT_s = m \times n + s Ts​=m×n+s

其中：

  • m：跨越一个磁道的平均移动时间；
  • n：跨越的磁道数；
  • s：启动磁臂的固定开销。

旋转延迟时间

旋转延迟是等待目标扇区转到磁头下的时间。

若磁盘转速为 r（转/秒），则平均旋转延迟近似为：

Tr=12rT_r = \frac{1}{2r} Tr​=2r1​

例如：

  • 若转速为 3600 r/min，则每转约 16.7 ms；
  • 平均旋转延迟约为 8.3 ms。

传输时间

传输时间与传输字节数、转速和每磁道容量有关：

Tt=brNT_t = \frac{b}{rN} Tt​=rNb​

其中：

  • b：读写的字节数；
  • r：磁盘转速；
  • N：每条磁道的字节数。

结论

磁盘总访问时间常常不是由数据传输时间主导，而是由机械运动开销主导：

  • 小块 I/O 中，寻道和旋转延迟远大于传输时间；
  • 连续大块 I/O 更容易摊薄固定开销。

这也是为什么顺序访问通常远快于随机访问。

磁盘调度算法

磁盘调度的目标是减少磁头移动距离，降低平均寻道时间，并兼顾公平性。

先来先服务 FCFS

按请求到达顺序处理。

优点：

  • 公平；
  • 实现简单。

缺点：

  • 不考虑磁头当前位置；
  • 可能导致磁头大范围来回移动，平均寻道时间较大。

最短寻道时间优先 SSTF

每次选择距离当前磁头位置最近的请求。

优点：

  • 通常能显著减少总寻道长度；
  • 平均性能优于 FCFS。

缺点：

  • 远离当前磁头的请求可能长期得不到服务；
  • 存在饥饿风险。

扫描算法 SCAN

也称电梯算法。

思想：

  • 磁头沿一个方向持续移动；
  • 依次处理沿途请求；
  • 到该方向没有请求后再反向。

特点：

  • 比 SSTF 更公平；
  • 能减少来回抖动；
  • 适合请求较多的场景。

循环扫描 CSCAN

思想：

  • 磁头只按一个方向扫描；
  • 到达一端后立即回到另一端重新开始扫描。

特点：

  • 各柱面等待时间更均匀；
  • 公平性比 SCAN 更好；
  • 代价是回卷过程本身不服务请求。

问题: 适合于访问磁盘上的顺序存储文件，不适合随机访问。

N-Step-SCAN 与 FSCAN

传统的 SCAN 算法像电梯一样，磁头在盘面上往复移动。在移动过程中，它会顺路处理所有遇到的 I/O 请求。

  • 问题所在：如果在磁盘读写的过程中，源源不断地有新的 I/O 请求发送到磁头当前所在的磁道（或相邻磁道）。
  • 后果：磁头就会像被“粘住”了一样，停留在原地不断地处理这些新来的请求，而无法继续向外移动。
  • 严重性：这会导致那些距离磁头较远的其他磁道上的 I/O 请求陷入无限期的等待（饥饿状态）。这在多用户、多任务的高并发系统中是非常致命的。

这两种算法用于避免“磁头粘黏”或长期偏向局部请求（饥饿）。

N-Step-SCAN：

  • 将请求分成长度为 N 的子序列；
  • 当前序列扫描期间，新请求进入后续序列；
  • N=1 时近似 FCFS，N 很大时接近 SCAN。

FSCAN：

  • 使用两个请求队列；
  • 一个队列供当前扫描使用；
  • 新到达请求进入另一个队列；
  • 扫描过程中当前队列不再增长。

优点：

  • 能限制单批请求规模；
  • 兼顾效率与公平性；
  • 避免新请求不断插入导致旧请求饿死。

磁盘组织与操作系统启动

分区与逻辑组织

磁盘通常会被划分为若干连续区域，每个区域称为分区（partition）。

分区表记录：

  • 起始扇区；
  • 大小；
  • 类型等元数据。

在分区基础上，文件系统进一步组织出卷（volume）：

  • 简单卷：来自单个分区；
  • 多分区卷：来自多个分区，可获得更大容量、更高性能或更强可靠性。

系统卷与引导卷

系统卷：

  • 保存引导程序等启动相关文件。

引导卷：

  • 保存 OS 核心文件，如内核映像等。

两者在某些系统中可以相同，也可以不同。

启动过程简述

操作系统启动通常经历如下过程：

  • 固件完成基本硬件初始化；
  • 从启动设备读取主引导记录或等价引导结构；
  • 装入引导程序；
  • 引导程序读取系统配置并装入内核；
  • 内核接管控制，继续初始化驱动、内存和进程管理。

磁盘存储空间管理

磁盘空间管理的核心任务是：

  • 记录哪些盘块空闲；
  • 在分配文件空间时快速找到可用块；
  • 在文件删除后正确回收。

空闲表法

基本思想：

  • 将每一段连续的空闲区记为一个表项；
  • 表项内容通常包括“起始盘块号 + 连续空闲块数”。

优点：

  • 适合连续文件分配；
  • 易于找到大块连续空间。

缺点：

  • 回收时可能需要合并相邻空闲区；
  • 当外存碎片严重时，表项会增多。

空闲链表法

把所有空闲块或空闲区串成链表。

两种方式：

  • 空闲盘块链：每个空闲块都链起来；
  • 空闲盘区链：每个结点表示一段连续空闲区。

优缺点：

  • 若按块组织，分配和回收过程简单，但链会很长；
  • 若按区组织，分配和回收过程较复杂，但链较短。

位示图法

为每个物理块设置一位：

  • 0 表示空闲；
  • 1 表示已分配。

优点：

  • 表示紧凑；
  • 适合成批扫描和快速统计；
  • 很容易和内存中的位运算结合。

缺点：

  • 对超大磁盘，位图本身也可能较大；
  • 找连续空闲区时仍需扫描。

成组链接法

UNIX/Linux 常见思想：

  • 将空闲块分成若干组；
  • 每组的第一个空闲块登记了下一组空闲块的物理盘块号和空闲块总数；
  • 如果一组的第一个空闲块号等于0，意味着该组是最后一组。

优点：

  • 减少空闲块管理元数据访问频率；
  • 兼顾链式组织和批量分配效率。

保证磁盘可靠性

RAID 的基本思想

廉价磁盘冗余阵列 RAID（Redundant Array of Inexpensive/Independent Disks）通过把多个磁盘组织成一个逻辑整体，以获得：

  • 更大的容量；
  • 更高的吞吐量；
  • 更强的容错能力。

对 OS 而言，RAID 往往像一块“更大、更快、更可靠”的磁盘。

三种基本手段：

  • 条带化（striping）：把连续数据切分后分散到多个磁盘，并行访问；
  • 镜像（mirroring）：保存数据副本；
  • 校验（parity）：保存冗余校验信息以便恢复。

RAID 0

只有条带化，没有冗余。

优点：

  • 并行读写性能好；
  • 容量利用率高。

缺点：

  • 任一磁盘损坏都可能导致整个阵列数据丢失；
  • 可靠性最低。

RAID 1

镜像阵列，数据写入两个副本。

优点：

  • 可靠性高；
  • 读性能可以提升。

缺点：

  • 有效容量减半；
  • 一个写操作，每个strip写两次；
  • 成本较高。

RAID 2

以字为单位（按位条带化），采用汉明码纠错冗余的磁盘阵列，将数据位交叉写入几个磁盘中。

  • 1，2，4位作为奇偶校验位，其他4位做数据位
  • 7个磁盘同步旋转，7位汉明码同时写入7个驱动器按位或按字节交叉存储，并使用汉明码进行纠错。

特点：

  • 并行存取，各个驱动器同步工作；
  • 纠错能力强；
  • 需要多个磁盘来存放汉明校验码信息，冗余磁盘数量与数据磁盘数量的对数成正比；
  • 现实中较少使用。

RAID 3

采用奇偶校验冗余的磁盘阵列，也采用数据位交叉，阵列中只有一个校验盘。

例如 盘1：A 盘2：B 盘3：C 校验盘：P=A⊕B⊕CP = A ⊕ B ⊕ CP=A⊕B⊕C 如果某一块数据盘坏了，比如盘2损坏，那么可以通过： B=A⊕C⊕PB = A ⊕ C ⊕ PB=A⊕C⊕P 恢复出原来的数据。

特点：

  • 适合大块顺序传输；
  • 将磁盘分组，读写要访问组中所有盘，每组中有一个盘作为校验盘；
  • 缺点：恢复时间较长，只能处理固定位置的磁盘纠错。

RAID 4

采用数据块级条带化和单独校验盘。

优点：可以并行进行多个数据的磁盘操作。

缺点：写入需要更新校验盘，负担较重，成为瓶颈（不管阵列里有多少块数据盘，只要有多个写操作同时发生，校验盘就会成为严重的交通堵塞点）。

RAID 5

数据块和校验信息都分布在各个磁盘上，没有专门的校验盘。

优点：

  • 既有较好的容量利用率，又有容错能力；
  • 避免单一校验盘瓶颈。

缺点：

  • 写入逻辑较复杂；
  • 磁盘故障后的重建开销大。

RAID 6

在 RAID 5 基础上增加一组独立冗余信息（双维校验）。

优点：

  • 可容忍两块磁盘同时损坏；
  • 可靠性更高。

缺点：

  • 冗余开销更大；
  • 写入代价更高。

RAID 小结

条带化：

  • 优点是并行、吞吐高、负载均衡；
  • 缺点是可靠性降低。

镜像：

  • 优点是恢复简单、可靠性强；
  • 缺点是容量开销大。

校验：

  • 优点是能用较少冗余换取容错；
  • 缺点是写入和恢复逻辑更复杂。

提高 I/O 速度

总体思路

提高磁盘 I/O 速度的主要方法：

  • 选择性能更好的硬件；
  • 采用并行化；
  • 选用合适的磁盘调度算法；
  • 使用高速缓存；
  • 优化物理布局；
  • 进行提前读和延迟写。

磁盘高速缓存

磁盘缓存的作用：

  • 将最近访问的数据保存在更快的存储介质中；
  • 减少真实磁盘访问次数。

常见形式：

  • 独立缓存（固定大小）；
  • 使用主存的一部分作为页缓存或缓冲区（虚拟内存）缓存。

数据交付

  • 直接交付（copy开销）
  • 指针交付（内存管理复杂）

常见策略：

  • 置换算法，如 LRU；
  • 周期性写回；
  • 脏块延迟落盘。

优化数据布局

通过优化数据物理摆放，也能显著改善性能： 优化物理块的分布

  • 连续摆放 -> 顺序访问速度大于随机访问

优化索引节点的分布

  • 减少与数据块的距离
  • 与数据块结合 一次读取

提前读

对于顺序访问，OS 常在读取当前块时顺便把后续块提前读入缓存。

优点：

  • 减少下一次等待时间；
  • 提升顺序访问吞吐量。

延迟写

修改后的数据先写入缓存，不立即落盘，而是在适当时机批量写回。

优点：

  • 合并写操作；
  • 减少磁盘访问次数；
  • 提升整体吞吐。

风险：

  • 断电或系统崩溃时可能丢失尚未落盘的数据。

虚拟盘

虚拟盘（RAM Disk）是利用内存模拟磁盘。

特点：

  • 速度极快；
  • 内容通常由用户或系统显式控制；
  • 掉电易失。

与磁盘缓存的区别：

  • 虚拟盘中的内容是“逻辑上当作磁盘使用”的；
  • 缓存中的内容由 OS 自动决定和替换。

磁盘管理实例

基本盘与动态盘

在一些系统中，磁盘可分为：

  • 基本盘：传统分区方式；
  • 动态盘：支持更灵活的卷管理。

动态盘通常支持：

  • 跨磁盘卷；
  • 条带卷；
  • 镜像卷；
  • RAID-5 卷。

多分区卷

常见形式：

  • 跨分区卷（spanned volume）：把多个空闲分区拼接成一个逻辑卷；
  • 条带卷（striped volume）：跨多个磁盘按条带分布数据，对应 RAID-0 思想；
  • 镜像卷（mirrored volume）：数据写双份，对应 RAID-1；
  • RAID-5 卷：条带化加分布式校验。

安装管理与卷名字空间

系统通常需要维护：

  • 物理磁盘对象；
  • 卷对象；
  • 驱动器号或挂载点；
  • 逻辑名字到设备对象的映射关系。

例如：

  • 通过卷 GUID 唯一标识卷；
  • 通过驱动器号或挂载点向用户程序暴露访问入口；
  • 通过 I/O 管理器把逻辑请求映射到具体分区和磁盘。

小结

本章核心内容：

  • 磁盘是典型的机械式随机存取设备，访问时间由寻道、旋转延迟、传输三部分构成；
  • 磁盘调度算法的核心是减少磁头移动并兼顾公平性；
  • 空闲空间管理常见方法有空闲表、空闲链、位示图和成组链接；
  • RAID 通过条带化、镜像和校验提升性能与可靠性；
  • 提高 I/O 性能不仅靠硬件，更靠缓存、调度和布局优化；
  • 现代 OS 还需要在分区、卷、挂载和启动流程上完成完整的磁盘抽象。
