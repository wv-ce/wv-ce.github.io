OS 理论笔记：文件系统

文件系统

文件系统基本概念

数据的持久化存储

进程运行时可以把数据暂时保存在自己的地址空间中，但这种方式有明显局限：

  • 地址空间大小有限；
  • 进程结束后，数据会丢失；
  • 不便于多个进程长期共享。

因此，计算机必须把部分数据保存在磁盘、SSD、光盘等外部存储设备上，以满足：

  • 大量存储；
  • 长期保存；
  • 多进程共享。

文件的概念

文件（File）是带有标识（文件名）的、在逻辑上具有完整意义的信息项序列。

可以从两个角度理解文件：

  • 从用户角度：文件是一个有名字的字节序列；
  • 从文件系统角度：文件是磁盘块的有组织集合。

文件通常包括两部分：

  • 文件体：文件的实际内容；
  • 文件说明：管理该文件所需的信息，如文件名、物理地址、大小、权限、时间戳等。

文件的本质

文件本质上是一种抽象机制。

操作系统中的典型抽象：

  • 进程是对 CPU 的抽象；
  • 虚拟地址空间是对内存的抽象；
  • 文件是对磁盘等持久化存储的抽象。

文件把底层复杂的存储细节隐藏起来，使用户看到的是一个独立的、连续的逻辑地址空间，其大小就是文件大小，与进程地址空间无关。

一切皆文件

文件的本质是一组字节序列，因此很多 I/O 设备也可以被视为字节流的载体：

  • 字符设备；
  • 块设备；
  • 网络设备。

这就是现代操作系统中“一切皆文件”的基本思想。

文件管理与文件系统

文件管理的需求

从用户视角看：

  • 关心文件怎么命名；
  • 关心如何创建、打开、关闭、读、写；
  • 关心共享和保护；
  • 不关心数据具体存放在磁盘哪里。

从操作系统视角看：

  • 需要组织和管理物理文件；
  • 需要维护目录、存储空间和元数据；
  • 需要完成逻辑地址到物理地址的转换；
  • 需要与设备管理和 I/O 系统对接。

文件系统的定义

文件系统（File System）是操作系统中统一管理信息资源的软件，负责：

  • 文件的存储；
  • 文件的检索；
  • 文件的更新；
  • 文件共享；
  • 文件保护；
  • 用户接口提供。

文件系统的任务

文件系统通常需要完成以下任务：

  1. 统一管理磁盘空间，实现分配和回收；
  2. 实现文件的按名存取；
  3. 提供共享、保护和保密机制；
  4. 向用户提供方便的操作接口；
  5. 提高文件系统性能；
  6. 提供与 I/O 系统的统一接口。

文件系统模型

文件系统可以理解为多个层次模块的组合：

文件系统的三个层次

第一层：文件系统接口

  • 命令行接口：用户通过命令与文件系统交互；
  • 程序接口：用户程序通过系统调用访问文件系统。

第二层：文件管理的软件集合

  • 存储空间管理；
  • 目录管理；
  • 逻辑块到物理块映射；
  • 文件读写管理；
  • 共享与保护。

第三层：文件系统管理对象

  • 文件；
  • 目录；
  • 磁盘存储空间。

文件名、文件类型与文件属性

文件名

创建文件时必须指定文件名，用户依靠文件名访问文件。

常见规则：

  • 文件名是一个有限长度字符串；
  • 常常由“文件名 + 扩展名”组成；
  • 不同系统对最大长度、大小写是否敏感的规定不同。

文件类型

可以从多个角度分类文件。

按性质和用途：

  • 系统文件；
  • 库文件；
  • 用户文件。

按数据形式：

  • 源文件；
  • 目标文件；
  • 可执行文件。

按保护级别：

  • 只读文件；
  • 读写文件；
  • 执行文件；
  • 不保护文件。

按逻辑结构：

  • 有结构文件；
  • 无结构文件。

按物理结构：

  • 顺序文件；
  • 链接文件；
  • 索引文件。

UNIX 中的典型文件类型

UNIX 常见文件类型：

  • 普通文件：用户自己创建的文件，一般为ASCII或二进制文件；
  • 目录文件：管理文件系统的系统文件；
  • 特殊文件（设备文件）；
  • 管道文件；
  • 套接字文件。

其中：

  • 字符设备文件对应串行 I/O 设备；
  • 块设备文件对应磁盘、磁带等；
  • 管道和套接字体现了“把通信对象也抽象成文件”的思想。

文件的逻辑结构

逻辑结构的含义

文件逻辑结构是从用户角度看到的文件组织方式，主要由访问需求决定。

典型形式：

  • 字节流；
  • 记录序列；
  • 树形结构。

流式文件与记录式文件

流式文件：

  • 以字符或字节为基本单位；
  • 文件内容是一串无结构的字节序列；
  • 典型于文本文件、二进制文件。

记录式文件：

  • 由若干记录组成；
  • 每条记录有内部结构；
  • 可以按记录读写、查找和修改。

文件存取方式

常见存取方式：

  • 顺序存取；
  • 随机存取。

随机存取通常需要显式指定读写位置或偏移量。

文件存储介质

文件最终存放在外部存储设备上。磁盘、SSD 等设备通常被划分为大小相等的物理块（block）或簇（cluster）：

  • 它们是存储、传输和分配的基本单位；
  • 系统统一为这些块编号。

文件控制块与文件基本操作

文件控制块 FCB

文件控制块（FCB, File Control Block）是操作系统为了管理文件而设置的数据结构。

它保存管理文件所需的各种元数据。在很多系统中，目录项本质上就是文件控制块的一种表现形式。

FCB 常见内容：

  • 文件名；
  • 文件号；
  • 文件大小；
  • 文件物理地址；
  • 文件逻辑结构和物理结构；
  • 创建时间、修改时间、访问时间；
  • 所有者、创建者；
  • 访问权限；
  • 文件类型；
  • 共享计数；
  • 各种状态标志。

文件基本操作

文件的常见操作包括：

  • 创建 create；
  • 删除 delete；
  • 打开 open；
  • 关闭 close；
  • 读 read；
  • 写 write；
  • 追加 append；
  • 定位 seek；
  • 获取属性 get attributes；
  • 设置属性 set attributes；
  • 重命名 rename。

目录管理

为什么需要目录

如果系统中文件很多，必须解决几个问题：

  • 如何快速定位一个文件（效率）；
  • 如何避免不同用户之间的命名冲突；
  • 如何按用途、类型、课程、用户等进行分组。

目录就是为了解决这些问题而提出的。

目录的定义

目录是由文件说明索引组成的、用于文件检索的特殊文件。

目录中保存的主要是文件访问和控制信息，而不是文件内容本身。

目录项内容

目录项通常包含：

  • 基本信息；
    • 文件名；
    • 别名的数目；
  • 文件类型；
  • 地址信息；
    • 存放位置；
    • 文件长度；
  • 访问控制信息；
    • 所有者；
    • 访问权限；
  • 创建、读写时间等使用信息。

从这个意义上说：

  • 目录项就是文件控制块；
  • 目录文件是 FCB 的集合。

目录操作

常见目录操作：

  • 创建目录；
  • 删除目录；
  • 打开目录；
  • 关闭目录；
  • 读取目录项；
  • 重命名目录；
  • 建立链接；
  • 删除链接。

文件目录的组织方式

单级目录

单级目录是最简单的目录结构，所有文件都放在同一个目录下。

优点：

  • 结构简单；
  • 易于实现。

缺点：

  • 文件多时查找慢；
  • 文件名容易冲突；
  • 不便于共享和分类管理。

两级目录

两级目录的结构是：

  • 根目录下按用户划分目录；
  • 每个用户目录中存放该用户文件；
  • 用户目录下不再继续细分。

优点：

  • 适合多用户系统；
  • 可避免不同用户间的重名问题。

缺点：

  • 用户自己的文件仍然缺乏更细粒度分组。

多级目录

多级目录（层次目录）是现代操作系统最常见的方式。

特点：

  • 高层目录项指向下一级目录；
  • 最后一层目录项指向实际文件；
  • 形成一棵目录树。

优点：

  • 层次清晰；
  • 便于分类管理；
  • 能解决文件重名问题；
  • 便于不同用户和不同类别文件分别设置权限；
  • 分级查找通常比单级目录更高效。

缺点：

  • 当目录层次过深时，路径检索时间会增加。

路径名

在多级目录中，访问文件需要路径名。

绝对路径名：

  • 从根目录开始，逐级写出到目标文件的完整路径；
  • 对同一文件是唯一的。

相对路径名：

  • 相对于当前工作目录指定路径；
  • 依赖于当前目录位置。

特殊目录：

  • . 表示当前目录；
  • .. 表示上一级目录。

文件系统的实现方法

文件实现本质上要解决两个问题：

  1. 如何描述一个文件，如何记录其管理信息；
  2. 如何存放文件，如何记录逻辑块与物理块之间的映射关系。

第一个问题主要由 FCB/inode 等元数据结构解决。
第二个问题主要由文件物理结构和块映射方式解决。

磁盘上文件系统的布局

典型的磁盘文件系统布局中，通常会包含：

  • 引导块；
  • 超级块；
  • 空闲空间信息；
  • inode/FCB 区；
  • 数据区。

超级块

超级块（superblock）记录文件系统整体特征，例如：

  • 文件系统大小；
  • 块大小；
  • 空闲块数量；
  • 已使用块数量；
  • inode 信息等。

系统在挂载文件系统时通常需要读取超级块。

如果超级块损坏，文件系统往往无法被正常加载。

文件逻辑结构与物理结构

文件逻辑结构：

  • 从用户角度看文件如何组织；
  • 目的是提高检索效率、便于修改、降低文件存储开销、降低使用复杂度。

文件物理结构：

  • 表示文件在外存中的存放方式（位置、链接和编目的方法）；
  • 解决物理块组织和逻辑块映射问题。

常见物理结构：

  • 连续文件；
  • 链接文件；
  • 索引文件。

连续文件

基本思想

连续文件要求一个文件占用一组连续的物理块。

目录项中通常只需要记录：

  • 起始块号；
  • 占用块数。

因此，逻辑块号到物理块号的转换非常直接：物理块号 = 起始块号 + 逻辑块号

优点

  • 结构简单，实现容易；
  • 不需要额外链接或索引空间；
  • 支持顺序访问；
  • 也支持随机访问；
  • 顺序和随机访问速度都较快。

缺点

  • 文件长度不易动态增长；
  • 创建时常需要预估大小；
  • 预留空间可能浪费；
  • 删除后容易产生外部碎片；
  • 若需要扩展文件，可能必须整体搬移。

删除文件导致碎片化

连续文件适合长度变化不大、顺序访问为主的文件，如部分多媒体文件。

串联/链接文件

基本思想

链接文件（串联文件）由若干离散物理块组成，每个物理块的最末一个字（或第一个字）作为指针，指出后继块的物理地址。

目录项中保存链首指针，最后一个块用空指针（“∧”）表示结束。

优点

  • 空间利用率高；能较好的利用辅存空间。
  • 文件动态扩充和修改容易。
  • 顺序存取效率高

缺点

  • 数据地址一起保存，随机存取效率太低，如果访问文件的最后的内容，实际上要访问整个文件。
  • 可靠性问题，如指针出错
  • 链接指针占用一定的空间

使用内存表的串联文件结构

将所有链表的指针放入一个内存表：文件分配表（FAT）

优点

  • 不用将数据和地址一起保存
  • 随机访问相对串联系统快速
    • 不必访问磁盘读出每块数据

缺点

  • 整个FAT必须在内存中
  • 非常占用空间
    • 1TB磁盘，1KB 块大小，1 billion表项，3byte每项，2.4GB
  • 随机访问仍然很慢 O(n)O(n)O(n)

索引文件

基本思想

索引文件为每个文件建立索引块，索引块中记录该文件各逻辑块对应的物理块号。

目录项中只需记录索引块位置。

访问文件时：

  • 先找到索引块；
  • 再由索引块找到目标数据块。

优点

  • 支持高效随机访问；
  • 文件块可以离散分布；
  • 不必要求连续空间；
  • 较适合大文件和频繁随机访问场景。

缺点

  • 需要额外索引块空间；
  • 小文件可能显得开销偏大；
  • 当文件很大时，可能需要多级索引。

文件物理结构的比较

三类物理结构的对比

连续文件：

  • 目录项中只需记录首块号和文件长度；
  • 不需要额外索引空间；
  • 随机访问效率最高。

缺点：

  • 文件动态增长和缩小时开销很大；
  • 创建文件时常要预估大小；
  • 易产生外部碎片，空间浪费较大。

串联文件：

  • 动态增长和缩小都比较方便；
  • 更适合顺序访问。

缺点：

  • 随机访问效率低；
  • 需要维护指针，可靠性受链指针影响；
  • FAT 改进了随机访问，但引入了额外内存开销。

索引文件：

  • 同时适合顺序访问和随机访问；
  • 文件块可离散分布；
  • 是综合性能较好的物理结构。

缺点：

  • 需要索引块空间；
  • 小文件的索引开销相对明显；
  • 查找时也要付出索引访问代价。

一个常见结论： 连续文件追求访问速度，串联文件追求动态扩展，索引文件在两者之间取得较好的折中。

目录的实现

目录的主要功能

目录的核心任务是：根据用户给出的文件名或路径名，迅速定位到相应的 FCB / inode；

从实现上看，目录系统通常要解决三个问题：

  • 目录项里放什么；
  • 长文件名如何存；
  • 目录如何查找。

目录的两种基本实现方法

直接法

直接法中，目录项直接包含：

  • 文件名；
  • FCB 本体，也就是文件属性信息和外存位置。

特点：

  • 查到目录项就等于查到了文件元数据；
  • 实现简单。

典型代表：

  • MS-DOS / 早期 Windows 风格目录项。
间接法

间接法中，目录项只保存：

  • 文件名；
  • FCB 的地址或索引号。

在 UNIX 类系统中，这个“索引号”通常就是 inode 号。

特点：

  • 文件名与文件元数据分离；
  • 支持多个文件名指向同一个 inode；
  • 共享和硬链接实现更灵活。

长文件名的实现

早期系统的文件名长度限制较小：

  • MS-DOS 经典格式是 8.3；
  • Unix V7 的文件名长度上限是 14。

现代系统普遍支持更长、可变长度的文件名，典型实现有三种：

  1. 目录项中预留固定大字段 例如每个目录项都固定预留 255 字符文件名空间。

    • 大量浪费空间，因为绝大多数文件名都不会这么长。

  2. 可变长目录项 目录项分成三部分：

    • 目录项总长度；
    • 固定长度属性信息；
    • 可变长文件名。

    缺点：

    • 删除文件后，原目录项空间不容易高效复用；
    • 目录内部更容易产生碎片。

  3. 目录项固定，文件名单独存放 目录项本身保持固定长度，把变长文件名统一放到目录文件的尾部或其他区域；目录项中仅保存文件名位置和长度。 特点：

    • 兼顾了目录项组织规则和长文件名支持；
    • 比完全可变长目录项更容易管理。

目录查询方法

顺序查找

  • 从头到尾依次扫描目录项；
  • 将目录项中的文件名与目标名字逐一比较。
  • 只适合目录项数量较少的场景。

Hash 查找

  • 使用 Hash 函数把文件名映射到某个表项或桶中；
  • 在对应桶内继续查找。

优点：

  • 平均查找速度快；
  • 适合目录项较多的场景。

缺点：

  • 需要解决冲突；
  • 目录项动态变化时实现稍复杂。

便于共享的目录组织

如果多个用户要共享同一个文件，理想目标是：

  • 外存中只保存一份文件副本；
  • 不同用户可以用相同或不同名字访问它。

一种典型组织方式是有向无环图（DAG）目录结构：

  • 一个文件可以被多个目录项引用；
  • 这样共享不会复制文件内容。

这也是硬链接思想的基础。

文件保护

文件保护常见有三种思路：

  • 建立副本；
  • 定时转储；
  • 设置访问权限。

建立副本

把同一个文件保存到多个存储介质上；某份损坏时，可以用其他副本恢复。

优点：简单直接。 缺点：设备成本和系统开销都较大。 适用场景：短小但极其重要的文件。

定时转储

系统每隔一段时间把文件备份到其他介质；一旦文件损坏，就恢复到最近一次转储时的状态。

特点：

  • 比多副本更节省常驻空间；
  • 是 UNIX 等系统常用的可靠性保障方式之一。

局限：

  • 只能恢复到某个过去时刻；
  • 最近修改的数据可能丢失。

文件的存取控制

文件保护机制的目标包括：

  • 防止未授权用户访问文件；
  • 防止用户冒充别人访问文件；
  • 防止合法用户误操作关键文件。

一个典型的权限验证过程包括：

  1. 确定当前用户身份和所属权限；
  2. 判断其申请的访问方式是否被允许；
  3. 检查访问请求与文件保密级别是否冲突。

存取控制的实现方案

常见实现方法：

  • 存取控制矩阵；
  • 存取控制表（ACL）；
  • 用户权限表；
  • 口令保护。

在 UNIX 风格系统中，最经典的是基于三类用户的权限模型：

  • owner：文件拥有者；
  • group：同组用户；
  • public / others：其他用户。

每类用户通常有三种基本权限：

  • r：读；
  • w：写；
  • x：执行。

因此像 rwxr-xr-- 或数值 754 这类表示法，本质上就是三组 rwx 权限位的编码。

文件的并发访问

多个进程可能同时访问同一个文件，因此需要并发访问控制。

基本思路：

  • 访问文件前必须先 open；
  • 若文件目录项 / inode 尚未在内存中，则先从外存读入；
  • 若已在内存中，则多个进程共享同一份内存元数据；
  • 这样可以保持文件系统状态的一致性。

文件锁（file lock）用于协调多个进程对文件或文件某一段区域的互斥访问。

典型锁操作包括：

  • 加锁并阻塞等待；
  • 加锁但若失败则立即返回；
  • 解锁；
  • 测试是否可锁。

文件锁的作用：

  • 防止并发写破坏数据；
  • 避免读写交叉导致内容不一致。

除了文件锁，也可以通过进程间通信来协调文件访问次序。

文件系统性能优化

性能问题的根源

文件系统的主要瓶颈之一是磁盘访问速度。

因此，设计文件系统时的一个重要目标就是：

  • 尽量减少磁盘访问次数；
  • 尽量减少磁头移动和随机访问；
  • 提高热点数据的缓存命中率。

常见优化手段

常见性能优化方法包括：

  • 目录项 / FCB 分解；
  • 保存当前目录等常用状态；
  • 磁盘碎片整理；
  • 块高速缓存；
  • 磁盘调度；
  • 预读（read-ahead）；
  • 合理分配磁盘空间；
  • 信息优化布局；
  • RAID。

其中最重要、最常见的是块高速缓存。

块高速缓存

块高速缓存（block cache）也叫：

  • 文件缓存；
  • 磁盘高速缓存；
  • 缓冲区高速缓存。

它的本质是在内存中为磁盘块建立一个缓存区，保存部分磁盘块的副本。

工作方式：

  • 收到读请求时，先检查目标块是否已在缓存中；
  • 如果命中，则直接从内存返回；
  • 如果未命中，则先把块从磁盘读入缓存，再交给请求者。

块高速缓存的组织方式

常见组织方式：

  • 用双向链表把缓存块串起来；
  • 使用计数或状态位区分“正在使用”和“空闲”块；
  • 空闲块可挂在链尾等待复用；
  • 同时按块号建立散列表，加速缓存查找。

这样可以同时兼顾：

  • 快速查找块是否在缓存中；
  • 高效维护最近使用状态。

置换与写入策略

当缓存满时，需要考虑：

  • 置换哪个块；
  • 修改过的块何时写回磁盘。

设计要点：

  • 保留未来可能再次使用的热点块；
  • 尽量淘汰使用概率低的块；
  • 处理好缓存与磁盘的一致性问题。

典型策略包括：

  • 写回（write-back）；
  • 直写（write-through）。

文件系统在这里必须权衡：

  • 性能；
  • 数据安全；
  • 崩溃后一致性。

现代文件系统机制

虚拟文件系统 VFS

现代操作系统往往需要同时支持多种异构文件系统，例如：

  • Linux 分区使用 Ext4；
  • U 盘使用 FAT/exFAT；
  • 移动硬盘可能是 NTFS；
  • macOS 常见 APFS。

为屏蔽底层差异，操作系统通常引入虚拟文件系统（VFS）。

VFS 的作用：

  • 对上提供统一接口，如 POSIX 风格 open/read/write/close；
  • 对下对接不同具体文件系统驱动；
  • 把不同文件系统的元数据统一抽象成内存对象。

在 Linux 中：

  • VFS 定义了一组标准接口；
  • 各个具体文件系统实现这些接口；
  • 当系统访问某个 inode 时，VFS 会先确定它属于哪个文件系统，再调用对应实现。

写时复制 CoW 与快速复制

大文件复制往往很慢，因为传统做法需要真的把所有数据块复制一遍。

更快的方法是写时复制（Copy-on-Write, CoW）：

  • 新文件先与原文件共享同一批数据块；
  • 只有某一方后续修改数据时，才真正复制对应块。

优点：

  • “复制”操作本身几乎只改元数据；
  • 大文件也能做到近似瞬时复制。

快照 Snapshot

快照本质上也常依赖 CoW：

  • 对于基于 inode 表的文件系统，可以复制 inode 表或其关键入口；
  • 对于树状文件系统，可以复制树根；
  • 原有数据块或节点在后续修改前继续共享；
  • 只有写入时才复制。

快照的意义：

  • 以很低代价保存某一时刻的文件系统状态；
  • 便于备份、回滚和容灾恢复。

稀疏文件 Sparse File

如果一个文件中大部分内容都是 0，就称为稀疏文件。

典型例子：

  • 虚拟机镜像文件；
  • 某些数据库或预分配大文件。

优化思想：

  • 没必要真的为全 0 区域分配物理块；
  • 只记录“这些逻辑区间内容为 0”；
  • 实际读到这些区域时，再由系统返回 0。

好处：

  • 节省大量磁盘空间；
  • 对超大、稀疏分布数据尤其有效。

FUSE 用户态文件系统

FUSE（Filesystem in Userspace）是用户态文件系统框架。

意义：

  • 允许开发者在用户态实现文件系统逻辑；
  • 内核负责转发请求和基础安全边界；
  • 降低了开发和调试文件系统的门槛。

FUSE 常见接口分为两层：

底层 API：

  • 直接与内核交互；
  • 需要自己处理 inode、lookup 等细节；
  • 更灵活，但复杂度更高。

高层 API：

  • 以路径名为中心；
  • 不必直接处理底层 inode 细节；
  • 更适合快速实现功能。

文件系统实例分析

FAT / MS-DOS 文件系统

基本特点

MS-DOS 文件系统的典型特点：

  • 支持多级目录；
  • 没有真正的文件别名机制；
  • 没有完善的用户访问权限控制。

按发展阶段常分为：

  • FAT12：最大支持约 32MB；
  • FAT16：最大支持约 2GB；
  • FAT32：最大支持约 2TB。

FAT 的核心思想

FAT 文件系统以簇（cluster）为分配单位。

特点：

  • 文件系统元数据保存在引导扇区等结构中；
  • FAT 表记录每个簇的状态及下一簇位置；
  • 目录项通常固定大小；
  • 早期 FAT12/FAT16 中根目录大小固定。

FAT 表项可表示：

  • 空闲簇；
  • 坏簇；
  • 保留簇；
  • 已分配簇及其下一簇编号；
  • 文件结束标记。

因此 FAT 本质上是：

  • “链接文件”思想的内存表改进版；
  • 把链指针从数据块中抽出来，集中放到 FAT 中。

UNIX 文件系统

基本特点

UNIX 文件系统通常具有：

  • 多级目录；
  • 文件别名机制；
  • 用户访问权限控制；
  • 基于 inode 的索引式文件组织。

UNIX 中既支持：

  • 基于 inode 的硬链接；
  • 基于路径名的符号链接。

磁盘布局

经典 UNIX 文件系统布局通常包括：

  • Boot Record；
  • Super Block；
  • inode Table；
  • Data 区。

也就是：

  • 引导信息；
  • 全局元数据；
  • inode 表；
  • 文件和目录的数据块。

inode 思想

UNIX 类文件系统把“文件名”和“文件实体”分离：

  • 目录项保存“文件名 -> inode 编号”的映射；
  • inode 保存文件属性和块地址。

这样做的好处：

  • 目录查找和文件元数据管理分离；
  • 支持硬链接；
  • 支持多个文件名引用同一文件对象；
  • 文件重命名不需要移动文件数据。

目录查找过程

路径查找时，系统会把路径拆成各级目录名，逐级查找：

例如访问 /usr/include/sys/types.h 时：

  • 先进入 /usr；
  • 再进入 /usr/include；
  • 再进入 /usr/include/sys；
  • 最后在该目录中找到 types.h 对应的目录项和 inode。

在朴素实现下：

  • 每一级目录通常至少涉及读取目录 inode 和目录数据块；
  • 因此路径很深时，磁盘访问次数会明显上升。

课件给出的结论是：

  • 最坏情况下，若路径有 n 级目录，则访问文件前可能需要约 2n + 1 次磁盘访问。

Ext2 文件系统

超级块

Ext2 的超级块记录文件系统的整体信息，例如：

  • 文件系统基本大小；
  • 数据块大小；
  • 每组块数；
  • 修订级别；
  • 魔数（magic number）；
  • 空闲块、空闲 inode 等统计。

Ext2 经典魔数是：

0xEF53

它用于标识这是一个合法的 Ext2 文件系统。

块组结构

Ext2 把磁盘划分为多个块组（block group）。

每个块组通常包含：

  • 超级块副本或相关信息；
  • 块组描述符；
  • 数据块位图；
  • inode 位图；
  • inode 表；
  • 数据区。

这样做的好处：

  • 降低大磁盘上的集中管理开销；
  • 改善局部性；
  • 便于同时管理数据块和 inode。

块组描述符

块组描述符通常记录：

  • 数据块位图位置；
  • inode 位图位置；
  • inode 表起始位置；
  • 空闲块计数；
  • 空闲 inode 计数；
  • 已使用目录数。

Ext2 中的目录

在 Ext2 中，目录本身也是一种特殊文件：

  • 它也有自己的 inode；
  • 它的数据块中存放若干目录项；
  • 每个目录项记录“文件名 -> inode”的映射。

因此目录遍历本质上就是：

  • 读目录 inode；
  • 读目录数据块；
  • 找到目标文件名；
  • 再定位目标 inode。

inode 的多级索引

为了兼顾小文件和大文件，UNIX / Ext2 常采用多级间接索引结构：

  • 小文件用直接索引；
  • 更大的文件用一级间接索引；
  • 再大的文件用二级、三级间接索引。

这样设计的优点：

  • 小文件访问快；
  • 大文件也能被支持；
  • 索引空间与访问效率取得较好的平衡。

这个思想和分页系统中的多级页表很像：

  • 页表完成 virtual page -> physical page；
  • inode 完成 logical block -> disk block。

小结

从 531 行之后这部分内容看，文件系统后半章主要在讲五件事：

  • 三类物理结构的比较：连续、链接、索引各自适合什么场景；
  • 目录实现：直接法、间接法、长文件名、Hash 查找、共享目录；
  • 文件保护与并发：权限控制、备份转储、文件锁；
  • 性能优化：块高速缓存、减少磁盘访问、VFS、CoW、快照、稀疏文件、FUSE；
  • 实例分析：FAT 体现“内存表式链接”，UNIX/Ext2 体现“目录项 + inode + 多级索引”。

把整章串起来可以记成一句话：

  • 文件系统就是把“路径名 + 偏移量”一步步转换成“某个文件对象 + 某个磁盘块”，同时尽量做到安全、共享、高效、可扩展。
